# MomentumLab Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use momentumlab:subagent-driven-development (recommended) or momentumlab:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WordPress-Plugin `mlab-core`, das beim Kunden mit einem Lizenzschlüssel die MomentumLab-Plugins vom Lizenzserver anzeigt, per Klick installiert, aktiviert, deaktiviert und über den normalen WordPress-Update-Bereich aktuell hält.

**Architecture:** Ein `Client` spricht mit dem Lizenzserver (`mlab-ls/v1`, Header `X-MLAB-License` und `X-MLAB-Site`) und speichert den Katalog in einer Option. Eine reine Klasse `Row` leitet pro Produkt den Zustand für die Liste ab (testbar ohne WordPress). Installation über `Plugin_Upgrader`, Aktivierung über `activate_plugin()`, Updates über Plugin Update Checker v5 im JSON-Modus gegen `/update/<slug>`. Der Core selbst aktualisiert sich über sein öffentliches GitHub-Repo.

**Tech Stack:** PHP 8.0+, WordPress 6.4+, PHPUnit 9, PHPCS (WordPress), Plugin Update Checker v5.

**Spec:** `docs/momentumlab/specs/2026-10-17-core-und-lizenzserver-design.md`

**Server-Vertrag:** wie in `momentumlab-ch/mlab-license-server` PR #1:
- `GET /wp-json/mlab-ls/v1/catalog` → `{"products":[{"slug","name","description","version","main_file","unlocked"}]}`; Fehler als WordPress-REST-Fehler `{"code","message","data":{"status"}}` (401 `mlab_ls_invalid_license`, 403 `mlab_ls_site_limit`, 429, 503).
- `GET /wp-json/mlab-ls/v1/update/<slug>` → PUC-JSON mit `download_url` (10 Minuten gültig).

## Global Constraints

- Repo `momentumlab-ch/mlab-core` (öffentlich), Branch `claude/project-thread-oeiqg4`. Header `Requires at least: 6.4`, `Requires PHP: 8.0`, `Text Domain: mlab-core`, `Update URI: https://github.com/momentumlab-ch/mlab-core/`, GPL-2.0-or-later, `Version: 0.1.0`.
- Präfix `mlab_core_` / `MLAB_CORE_`, Namespace `MomentumLab\Core`. Jede PHP-Datei mit `defined( 'ABSPATH' ) || exit;`.
- Konstanten: `MLAB_CORE_SERVER_URL` (Default `https://momentumlab.ch`), `MLAB_CORE_LICENSE_KEY` (optional; wenn gesetzt, ist das Feld gesperrt).
- Server-Aufrufe nur im Admin oder im Update-Check von WordPress, Timeout 5 Sekunden, nie im Frontend. Katalog-Cache 12 Stunden.
- Rechte: Seite und Aktionen `install_plugins` für Installieren, `activate_plugins` für Ein/Aus, `manage_options` für den Schlüssel; jede Aktion mit Nonce, über `admin-post.php`.
- User First: ein Klick pro Plugin, deutsche Texte ohne Fachjargon, Fehlermeldungen sagen, was zu tun ist, auf dem Handy bedienbar (Karten statt breiter Tabelle).
- Ein abgelaufenes Abo oder ein nicht erreichbarer Server deaktiviert nie ein installiertes Plugin.
- Funktionen unter ca. 30 Zeilen, max. zwei Einrückungsebenen. Texte übersetzbar (`mlab-core`, Deutsch als Quelle).
- Keine Hinweise auf Claude oder KI. Git-Identität `MomentumLab Dev <support@momentumlab.ch>`, Commit-Format `vX.Y.Z — <type>: <beschreibung>`.
- Vor jedem Commit: `composer test` grün, `vendor/bin/phpcs -q` Exit 0 (Warnungen lassen CI scheitern). Composer mit `COMPOSER_ALLOW_SUPERUSER=1`, `config.platform.php` = `8.0.30`.

## Review Focus

- Server liefert 401/403/5xx oder ist nicht erreichbar → Liste zeigt den letzten gespeicherten Stand mit verständlichem Hinweis; bei 401 und 403 wird der gespeicherte Katalog verworfen (keine Freischaltung mehr sichtbar). (Test in Task 2)
- Produkt im Katalog, aber `main_file` nicht installiert und `unlocked` false → Zustand «Auf Anfrage», kein Knopf. (Test in Task 2)
- Installiertes, aktives Plugin, das nicht mehr freigeschaltet ist → bleibt aktiv, Knopf «Deaktivieren» bleibt, Hinweis «Keine Updates mehr». (Test in Task 2)
- `main_file` aus dem Server enthält `..` oder führt aus `wp-content/plugins` hinaus → wird verworfen. (Test in Task 2)
- Installation schlägt fehl (Download, Rechte, Ordner existiert) → Meldung mit Handlungsanweisung, kein halbes Plugin aktiv. (Test in Task 5)
